# 豆蜂 · WorkBuddy 抖音运营工作台

这是面向个人使用的本地内容与电商运营工作台，当前版本 **4.2.0**。商品研究、账号定位、视频制作记录、发布排期、复盘和备份都保存在自己的电脑。可选连接 WorkBuddy Skill、MCP Connector 和腾讯 BrowserSkill。

## 个人版快速开始

1. 本机需要 Node.js **20.11 或更新版本**，无需安装 npm 依赖。
2. 双击项目目录的 **`start.cmd`**。它会启动本地服务并在默认浏览器打开工作台。
3. 首次使用打开“账号与设置”填写账号名称，再开始选题或制作视频。
4. 日常在“总览”查看待发布、逾期和待复盘内容；在“数据管理”备份和恢复。

`start.cmd` 默认从 4174–4184 选择可用端口，重复运行会打开同目录已启动的服务。服务在后台运行，关闭浏览器不会停止服务。日志位于数据目录 `logs/`。如需前台运行和用 Ctrl+C 退出，可执行 `npm run serve`。

## 每日自动生产

“每日自动生产”支持 **资讯视频** 和 **商品介绍** 两种内容来源，共用每天最多一条的发布限制。默认每天北京时间 **06:00** 开工，也可在页面设置其他时间。首次使用默认资讯模式；已有商品计划保留原配置，点击“一键使用科技资讯”即可切换并暂停旧计划。

资讯模式的流程是：读取公开 RSS / Atom → 筛选最近 48 小时内未发布的资讯 → 免费制作 720×1280 信息卡字幕视频 → 通过现有抖音发布适配器提交。默认来源是 [IT之家 RSS](https://www.ithome.com/rss/)，可换成其他公开 HTTPS 订阅地址，也可填写逗号分隔的关键词（任一匹配，留空不过滤）。不需要商品库或每天手填脚本。当前按发布时间选择内容，没有热点排名数据。

### 一次设置

1. 打开“每日自动生产”，选择“资讯视频”，使用默认来源或点击“一键使用科技资讯”。需要筛选主题时填写关键词，再保存来源；这些操作只保存设置，不启动发布。
2. 点击“立即采集资讯”，查看最近采集的标题、时间和原文链接。以后每天开工会重新采集，自动跳过已经提交、已发布或结果待核实的资讯。
3. 查看“运行条件”清单，点击“检查运行条件”确认 Python、Pillow、imageio-ffmpeg、中文字体和 FFmpeg 可用。此操作只检查本机环境，不生成视频、不访问浏览器；缺少条件时按页面提示处理。
4. 登录抖音创作者中心并连接 BrowserSkill，点击“自动识别抖音账号”。只有一个连接时自动选择；已保存的浏览器连接失效且仅有一个可用连接时，也会回退到该连接。多个连接时在页面选择，并核对识别出的抖音号。
5. 保存每天的开工时间，可先点击“仅生成一条预览”查看成片。勾选每天自动制作并公开发布的授权后开启计划，系统会先检查运行环境；页面显示下次执行时间。开启时已过当天设置的时间，则从明天开始。更改内容模式、RSS、关键词或开工时间会暂停计划，需重新开启。
6. 在本页查看状态摘要，筛选执行记录，查看成片、错误与回执，或导出运行记录。生成的视频和草稿也会归档到视频制作台和发布计划。提交结果待核实时，可以登记核实结果和作品链接。

### 资讯视频的制作与异常处理

- 每条视频使用最多 3 条资讯，按完整标题、来源名称和发布时间绘制图卡，片头与片尾各 6 秒、每条资讯 8 秒，总时长 20 / 28 / 36 秒，配静音音轨。画面为本地生成的文字排版与几何背景，不调用付费模型，也不抓取文章全文、原站配图或他人视频。
- 画面注明“资讯标题速览·非现场画面”，发布说明保留完整来源链接。标题超过 120 字时跳过并记录原因；文案无法容纳完整出处时自动减少条数或跳过该条，不删减出处。
- 标题与原文链接同时去重，原文改标题后也不会重复发布。预览不消耗资讯；实际已提交、已发布或结果不明的内容不会再次入选。
- 没有近期新资讯时跳过当天，计划保持开启。采集失败时可使用 48 小时内未发布的缓存，并记录警告；缓存也为空则跳过，下个执行日继续采集。制作失败、账号失效或提交结果不明会暂停计划，处理原因后再开启。
- 每次最多读取 2MB RSS 内容、返回 60 条近期标题；请求限制为 30 秒、最多 3 次重定向。只连接公开 HTTPS 来源，不执行资讯内容中的指令。

### 保留的商品介绍模式

选择“商品介绍”并保存后，设置原选品项目的 `output`、日期或单品目录，点击“立即同步商品”。默认收件目录为数据目录下的 `product-inbox/`。以后每天开工前导入新日报和图片，再从商品库选择未发布商品，优先“准备推广”状态和较新的资料。同一日期与名称的商品只导入一次，已有编辑及回收站商品不会被覆盖或恢复；每次最多新增 50 款、读取 200MB 图片。

日报沿用原电商项目的目录格式：

```text
output/
  YYYY-MM-DD/
    商品名称/
      01_全链路分析.md
      02_货源比价.md
      03_价格单.md
      04_视频脚本.md
      05_发布文案.md
      06_素材/images/商品图.jpg
```

至少需要一份约定名称的报告和一张 PNG、JPEG 或 WebP 图片。来源目录里后续出现新日报时会自动导入；本功能不会执行报告中的指令，也不会启动上游 AI 任务生成日报。

- 商品图片和中文文案沿用已保存资料，没有文案时仅使用商品名称及中性介绍，不编造卖点；普通商品介绍不挂链接。成片为图片切换、字幕和静音音轨。
- 图片文件丢失的候选商品会跳过并记录原因。来源目录临时不可读时，若商品库已有可用商品，会继续使用库存并记录同步警告；没有可用商品时停止本次任务。

### 调度与保存

- “仅生成一条预览”不会开启发布。每日生产默认暂停，开启前检查运行环境与账号。一次确认每天自动制作并发布后，无需逐条审批；账号变化后需重新识别和核对。
- 每天最多一条，晚于计划时间 6 小时或跨日不补发。与原发布队列共用执行锁，两种计划不能同时启用；提交结果不明时停止，不自动重发。电脑、本地服务和浏览器须保持运行。
- 视频编码使用本机 Python 的 `Pillow`、`imageio-ffmpeg`。优先查找已安装的 WorkBuddy Python，也可通过 `DOUFENG_PYTHON` 指定解释器。中文字体可用 `DOUFENG_FONT` 指定。没有依赖时明确报错，不自动安装或调用付费模型。
- 运行记录、资讯缓存和合成素材保存在 `runtime/daily-production/`；每条资讯成片旁保留 `input.json`、`sources.json` 与 `cards/` 图卡。导入图片保存在 `runtime/uploads/`，商品、视频和草稿保存在工作区数据中；均跟随 `DOUFENG_DATA_DIR`。迁移或备份请停服后复制整个数据目录，页面导出的运行记录不包含视频和图片。

**尚未完成：**发布后的播放量与互动回采，以及整条每日生产链路的实机验证；1688 等来源的联网自动选品仍未接入。资讯模式已经独立于电商日报。新增代码未执行功能测试，历史测试通过结果不覆盖本次改动；没有启用真实发布计划。

## v4.2：本地视频每日自动发布

新增左侧 **每日自动发布**。首次打开文件夹和账号为空，每天时间默认 **20:00（北京时间）**，自动发布默认暂停。普通“发布计划”继续用于管理草稿；只有在新页面逐条批准的内容才能自动执行。

### 配置与使用

1. 在 Chrome / Edge 登录抖音创作者中心，启用已安装的 BrowserSkill 扩展连接；安装方式见下方 BrowserSkill 章节。
2. 打开“每日自动发布”，填写本机视频文件夹完整路径和每天时间，刷新浏览器列表、选择浏览器，然后保存设置。
3. 点击“检查浏览器与账号”。软件会打开自己的会话，读取可见的抖音号并检查上传入口；请核对识别出的抖音号。
4. 点击“扫描视频文件夹”。只扫描这一层的 MP4 / MOV / WebM，单文件最大 4GB，每次目录最多 500 个视频；新增内容全部处于待审批状态。以后放入新视频后需再次扫描。
5. 逐条预览视频，编辑标题和文案，确认账号、公开可见范围和具体日期时间，勾选确认后批准。每批准一条，自动占用下一个空闲的每日时间。扫描顺序按文件名排列，排期顺序按批准顺序决定。
6. 点击“开启自动发布”。请保持电脑不休眠、豆蜂服务和所选浏览器运行。关闭工作台标签页后服务仍能执行；电脑关机或服务退出时不会执行。

审批会复制视频到本地数据目录并保存 SHA-256 摘要。执行使用这个副本，原视频不会移动或删除。相同内容在同一账号的有效队列和发布记录中不能重复批准。更改时间、目录、浏览器或识别到不同账号会暂停并撤销尚未执行的审批；修改已批准文案前也须撤销批准。

### 执行与异常

- 每 15 秒检查队列，每个账号每天最多执行一条；超过预定时间 10 分钟或跨日不提交，不集中补发。
- 到点先核对账号，上传已批准副本、填写标题和文案，再核对公开可见、立即发布选项及内容后只提交一次。默认使用平台自动生成的封面；平台要求手选封面或补充声明时会停止，首版不自动处理这些额外步骤。
- 登录失效、验证码、账号变化、页面无法识别和失败会停止该条并暂停自动发布。处理原因后重新审批、重新开启。
- 平台明确提示成功后记录为“已提交待审核”，不当作审核通过或已公开。“核实发布结果”可记录最终作品链接。
- 点击发布后响应丢失，或服务在执行途中退出，会标为“结果待核实”。先到抖音查找作品，确认完全未发布后才能重新审批，系统不会自动重试。
- “暂停自动发布”会在提交前拦截正在处理的任务；若已经点击发布，仍会记录该次结果，无法撤回平台已接收的提交。
- 队列位于 `runtime/automation/queue.json`，审批副本位于 `runtime/automation/media/`，不通过 MCP 草稿工具或工作区 JSON 导入自动生成审批。历史副本会保留，请留足磁盘空间。迁移前关闭服务，复制整个 runtime，目录或浏览器变化后重新配置和审批。
- 执行锁在确认原进程已退出后自动恢复；若提示锁格式异常或队列写入锁持续占用，先关闭使用同一数据目录的全部豆蜂服务，备份目录并确认锁内 PID 已退出，再移除对应 `.lock`。不要在发布进行中手工删锁。

**抖音自动发布验证范围：**已完成静态检查和账号/上传入口检查；完整定时提交链路仍需实机验证。BrowserSkill 操作依赖当前页面结构；识别不完整时会停止并保留错误，不把未完成的提交记为成功。下方 B 站案例验证的是独立的 Agent 发布流程。

实现参考：[BrowserSkill 官方仓库](https://github.com/Tencent/BrowserSkill)。抖音另有要求应用权限和用户授权的[官方视频创建接口](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/create/create-video/)，本版使用用户选择的本机浏览器登录态，不采集 Cookie 或密码。

## B 站发布流程（Agent 执行）

已将一次实际发布中走通的步骤固化到 [B 站发布流程](references/bilibili-publish-flow.md)，项目和 WorkBuddy 技能均可按此执行。下次可以说：**“把这个视频发到 B 站：完整路径，标题是……，使用我的……账号。”** 明确授权后，Agent 会恢复或上传视频、填写内容、调整两种封面、单次提交并核实结果。

- 本地命令 `node scripts/bilibili-workflow.mjs --help`；准备清单参考 [JSON 示例](references/bilibili-publish-manifest.example.json)。
- `prepare` 保存视频副本、文案与 SHA-256；`begin-submit` 在最终点击前保存提交意图并拒绝并发/重复提交；`finish` 记录审核中、已发布或结果不明。
- 已提交、已发布、结果不明的相同视频会阻止再次准备。中断后先核实平台；没有自动超时解锁或盲目重试。
- 已发布历史可用 `import-receipt --file <已核实回执.json>` 归档，默认存入 `runtime/bilibili-publish/`；设置 `DOUFENG_DATA_DIR` 时存入其下的 `bilibili-publish/`，命令行 `--data-dir` 优先。备份时复制整个目录，工作区 JSON 导出不包含它。
- 本地工具只管理流程记录，不会自行上传、批准、点击投稿或识别审核结果。网页操作仍由 Agent 观察执行，现有每日队列只支持抖音。

**实发范围：**2026-10-16 已完成一条本地 AI 萌宠视频的 B 站上传、封面调整、AI 声明、投稿和“已发布”核实。当前页面结构和浏览器实例可能变化，流程不固定账号、会话 ID 或按钮坐标。后续本地回归覆盖清单状态、素材校验、防重复提交、回执及自定义数据目录；这些测试不执行网页投稿，也不代表抖音每日自动发布已完成实发验证。

## v4.1：整合电商选品项目

### v4.1.1 稳定性修复

- 日报导入只采用明确的单一金额；区间价格、负数和带备注的价格留空待核实，空白单元格不再误读为备注列。
- 实时利润校验所有费用与比例；商品保存验证实际日期及完整货源链接。
- 图文准备仅复用同平台、同商品、未发布的图文草稿，保留视频草稿。
- 素材移除、下拉选择和恢复中的编辑也会触发关闭提醒；发生商品版本冲突时可另存新商品。
- 商品图片先检查能否解码；上传接口检查图片类型和 20MB 限制。
- 修复 IPv6 本机访问、地址别名及错误请求的状态码；启动器提示仍在运行的旧版本服务。

### 使用流程

已将 [shop-dropshipping-automation](https://github.com/qq773901406-cmd/shop-dropshipping-automation) 的日报约定、价格表解析、商品卡片和多平台草稿流程接入同一个工作台。来源版本与适配范围见 `integrations/shop-dropshipping/upstream.json`。

1. 左侧打开 **电商选品**，点击“导入日报目录”，选择原项目的 `output`、某个日期目录或单个商品目录。也可直接“录入商品”。
2. 导入前预览商品、报告和图片数量；相同日期与名称的商品跳过，保留已有手工修改。
3. 打开“资料 / 成本”，填写同一币种的售价、采购成本、运费和平台费率，按需补充包装、广告和退货预留。
4. 生成 1080×1080 商品卡片或选品汇总 PNG，下载或保存到本机素材。
5. “准备发布”可分别创建抖音、小红书、B站、微博、知乎、Instagram、Facebook、YouTube 社区草稿，继续在发布计划中编辑、检查和排期。
6. “转为视频项目”将商品、目标观众和原始脚本带入制作台；“研究任务单”可交给 WorkBuddy 继续完善。

商品资料共用全局搜索、自动备份、导入导出和回收站。首次使用不填充虚构商品；GitHub 仓库不包含被忽略的历史 output，已有日报需由用户选择本机目录导入。

原项目的自动发布、浏览器登录、定时任务、图片搜索下载和企业微信推送未在本版执行或启用。现有接入以本地研究、素材制作和发布准备为范围；导出文案与素材清单的 JSON 是交接数据，不是上游 CLI 参数文件。详细格式和边界见 `integrations/shop-dropshipping/README.md`。

## v4.0 基础能力

- 待办总览：今日待发布、逾期计划、制作受阻、待复盘和近期内容。
- 发布计划：列表 / 月历、日期和状态筛选、草稿编辑、CSV 导出、发布前检查。时间按本机时区显示，排期本身不执行自动发布。
- 内容库：分类、全文搜索、分页、编辑记录与 CSV 导出。Ctrl / ⌘ + K 可搜索整个工作区。
- 数据管理：手动备份、最近 30 个自动快照、导入和恢复前的数量对比、恢复前保护备份。
- 回收站：选题、项目、草稿和运营记录删除后可恢复；永久删除需再次确认。
- 输入暂存：常用表单在切换页面和刷新时保留；关闭标签页后不保证保留未提交内容，请及时保存。
- 离线字体、移动端布局、可键盘操作的弹窗、表单校验和错误提示。

本版保留现有业务数据。首次修改时写入 schemaVersion 5，为旧工作区补充空的 products 集合，同时保存修改前快照。导入比当前软件更新的数据版本会被拒绝，缺失或重复记录编号也会提示修复。升级后请重启本地服务及正在运行的 MCP 进程。

## 视频制作流程

1. 打开“视频制作台”，新建项目或选择“小猫跳舞模板”；也可以在选题卡片上选择“转为视频项目”。
2. 编辑主角、场景、画幅；在“角色参考与视觉约束”中记录参考视频 URL、角色参考图和固定的毛色、造型、道具、背景。参考路径只是制作记录，实际生成时由 Agent 或选用的工具读取素材。
3. 为每镜安排一个清晰动作，在“参考、起止状态与验收”中填写参考图及起止状态。对照上一镜终点与下一镜起点，避免角色、道具或场景无故变化。总时长根据各分镜自动计算。
4. 记录计划使用的工具、预计费用与费用策略。价格未知时留空，不会当作免费。保存项目，预览或导出包含参考绑定、状态衔接和待处理项的 TXT 制作单，交给 Agent 或选择的生成工具。
5. 生成后填回每镜素材路径，播放检查角色外观、肢体、道具、构图和衔接，再标记通过或退回并记录问题；只重做不合格镜头。制作台显示待生成、待验收、通过和退回数量。更换已通过镜头的设定或素材会转回待验收，保留原备注；更改全片角色、场景、风格或画幅会重置所有通过记录。路径和验收均是记录，界面不会自动读取本地路径或判断画面质量。
6. 按动作选择片段入出点、完成剪辑和声音设计，上传成片或填写路径后标记“已完成”。原有项目仍可读取；复制项目或分镜会保留参考与计划，清空生成结果和验收，避免把上一版结果当作新片。

制作台目前提供镜头计划、素材记录和质量检查提示；云端生成由 Agent 或外部工具执行，尚无网页内的一键模型生成接口。修改共享视频模型后，需要重启本地服务及 MCP 进程再刷新页面。剧情技能可参考 [Drama Skills](https://github.com/zenstory-ai/drama-skills)，实际模型能力和费用以执行时的工具返回为准。
6. 点击“准备发布”，补充封面、文案、话题并更新草稿。同一项目重复点击会打开已有草稿。

### 编辑与查找

- 支持按名称、角色、场景、制作工具和备注搜索，并按状态筛选、按最近更新 / 名称 / 时长排序。搜索和筛选不会重置正在填写的表单。
- “复制项目”会把分镜带入编辑区，重置制作状态、成片路径、阻碍原因和预计费用，保存后才创建新项目。
- 分镜支持上移、下移和复制，并显示各镜头在整条视频中的时间段。
- 输入内容会暂存在当前标签页的 `sessionStorage`，刷新后可恢复；只有点击“保存制作项目”或 Ctrl / ⌘ + S，才加入工作区并同步。关闭标签页后不保证恢复未提交表单，重要内容请保存或导出。
- 恢复的表单若对应较旧版本或已删除的项目，会阻止直接覆盖；可重新打开最新项目，或“另存为新项目”。另存会保留当前表单内容，包括填写的成片路径。
- “预览提示词”可检查完整制作说明。剪贴板权限不足时会打开可手动复制的文本窗口。

### 成片上传与预览

- 制作表单支持选择 MP4、WebM、MOV 成片上传到本地工作区，显示上传进度并可取消。上传后填入实际文件路径，仍需保存项目进行归档。
- 已上传的文件可在页内播放和拖动进度。仅开放工作台 `uploads` 目录内的文件，其他本地路径作为文本保留；HTTP(S) 成片链接通过按钮在新页打开。
- MOV 和部分编码能否播放取决于浏览器，无法预览时可先转换为兼容的 MP4。删除项目不会删除素材文件或已有发布草稿。

视频制作台管理制作流程，不内置视频生成模型，也不自动调用付费服务。成片经“每日自动发布”单独审批后可定时提交。费用由操作者填写，工作台不检查外部链接的可用性或实际报价。

WorkBuddy 可通过 `workspace_get` 的 `videos` 集合读取项目，使用 `video_project_save` 保存、`video_project_prompt` 获取提示词。更新项目须带上读取时的 `updatedAt` 作为 `expectedUpdatedAt`，防止覆盖较新的修改。

### Windows 后台持续运行

需要无人值守时，可由当前用户的 Windows 计划任务托管工作台和 BrowserSkill。先在本机 `runtime/background-services/config.json` 配置 `root`、`dataDir`、`port`、`nodeBinary`、`bskBinary`，路径均用绝对路径；可选 `bskHome` 必须沿用当前 BrowserSkill 数据目录，省略时使用当前用户默认目录。本机配置、任务登记、状态和诊断日志只保存在 runtime。

在 PowerShell 7 中执行：

```powershell
./scripts/register-background-services.ps1 -Config (Resolve-Path ./runtime/background-services/config.json).Path
```

该命令用本机 .NET Framework 编译无控制台的 WinExe 宿主，安装当前用户登录时启动的隐藏任务并立即启动，不保存密码、不要求以最高权限运行。任务每分钟也会触发一次存活兜底；`IgnoreNew` 保证健康任务保持运行，没有默认的 72 小时执行上限。WinExe 在自有 JobObject 中启动 supervisor，宿主意外退出时由 Windows 回收这次启动的进程树，再由下一次触发恢复；外部已运行且被复用的服务不在这个 JobObject 中。supervisor 每 30 秒检查服务，确认服务已退出后退避恢复；权限错误、超时和其他项目占用端口会保留诊断，不会强杀未知进程。BrowserSkill 使用 foreground 模式，空闲期限为 60 分钟；服务恢复不会重启已消费的单次发布，也不会更改发布授权或回执。

重复注册会校验任务的当前用户、权限、项目路径和精确启动参数，幂等复用符合配置的任务；原 PowerShell 宿主只有完全匹配本项目旧配置时才迁移。需要迁移或重新编译且任务仍运行时，命令会报错并保持原任务运行，应先确认没有进行中的发布再明确停止自己的任务。编译产物和构建校验保存在 `runtime/background-services`，不写入通用源码。

需要真正暂停后台宿主时，先核对 `runtime/background-services/task-registration.json` 中登记的任务确属当前项目，再对该精确任务名先执行 `Disable-ScheduledTask`，然后执行 `Stop-ScheduledTask`。只停止而不禁用会被每分钟触发重新拉起；不要按名称批量停止其他任务或进程。暂停后台宿主也会停止它拥有的工作台和 BrowserSkill，操作前应确认没有进行中的发布。

`runtime/background-services/state.json` 记录当前 PID、健康状态、退出原因和恢复次数；`events.jsonl` 保留有容量上限的事件日志；`host-events.jsonl` 仅记录宿主时间、PID 和启动退出状态，不保留被丢弃的子进程输出；`task-registration.json` 记录本机任务名。注册完成后还需要在独立终端检查工作台接口、BrowserSkill 扩展连接和真实只读会话，并观察完整回采周期。后台任务仍要求用户保持 Windows 登录、电脑唤醒、浏览器已登录；它不能代替登录或验证码。

## 数据说明

- 浏览器端保留本地副本，服务端同步到 `runtime/workbench.json`。顶部状态栏确认是否同步成功。
- 保存请求串行发送。HTTP 和 MCP 共用文件锁与临时文件替换，每次成功写入前将上一版保存为同目录 `.bak`。
- 工作区每次变更还会将上一版写入 `runtime/backups/`，自动快照保留最近 30 个；手动备份和恢复前保护备份持续保留。
- “数据管理 → 查看 / 恢复”会先显示恢复前后的账号与条目数量，确认后检查数据版本、备份当前数据，再替换工作区。
- “导入 JSON”接受导出的工作区 JSON 和 v1 备份封装，单文件上限 8MB。恢复需要当前同步已完成；冲突时先处理顶部提示。大量报告可能超过浏览器暂存配额，顶部会提示导出备份，服务端数据仍按实际同步结果保存。
- 回收站保存在工作区 JSON 中。移入回收站不会删除素材，也不会自动删除其他记录的引用；恢复同编号内容时会阻止覆盖现有记录。
- 网页提交带上读取时的版本。服务端数据有变化时返回 409，本页内容仍保留；先导出本页备份，再“载入最新数据”，按需合并修改。
- 刷新会恢复本页未同步内容。其他页面遗留的备份可从“未同步备份”中导出、载入或移除。
- JSON 损坏或不符合数据模型时，服务会报错并保留原文件。先复制原文件留档，再检查 `.bak` 恢复，避免继续覆盖。
- 异常退出可能留下 `.lock`。若重试后仍无法保存，先关闭使用该数据目录的 HTTP 服务和 MCP 进程，确认锁内 PID 已退出，再移除对应 `.lock` 文件并重启。
- `/api/state`：GET 返回 `{ state, revision }`；PUT 接收完整工作区对象，并要求 `If-Match: <revision>`。缺少版本返回 428，版本冲突返回 409。
- 素材准备目录为 `runtime/uploads`。
- 工作区 JSON 备份不包含素材文件、回采计划 `jobs.json`、执行日志 `activity.json` 和 `automation/` 自动发布队列及审批副本。迁移整套数据时，关闭服务及 MCP 后复制整个 runtime 目录；保留目录外素材的原文件，移动路径后需更新项目中的素材路径。
- `/api/media?path=<已上传素材的完整路径>` 支持 GET / HEAD 与单段 Range 请求；会检查实际文件路径，拒绝目录外文件和指向目录外的符号链接。
- 静态服务只提供页面所需文件，不公开 runtime、Git 目录和服务器源代码。
- Connector 不保存账号密码、Cookie、Token 或验证码。
- 页面内容只作为数据处理，不作为 Agent 指令。

`dist/doufeng-personal-4.2.0.zip` 为内容与电商个人版源码便携包，不包含 Node.js、BrowserSkill、现有 runtime、浏览器缓存或账号数据。其他 ZIP 为历史发布包。安装 Connector 时应上传完整 `workbuddy/connector`（包括 `lib`）。
