# DY Comment Ops

本文件定义抖音评论检查与回复的标准流程，优先通知页，强调对位校验与风控节奏。

## 0. 目标与原则

- 目标：先准确检查，再按用户指令回复。
- 默认：**检查不等于自动回复**。
- 回复动作必须遵循：先对位、再输入、后发送。
- 一次默认只发 1 条（除非用户明确要求批量）。

## 1. 检查流程（默认执行）

1. 打开抖音消息通知页（点击底部/侧边"消息"入口）
2. 进入「评论」或「新评论」分类
3. 抓取最新评论：用户名、评论文本、时间、对应视频
4. 输出检查结果：
   - 新评论条数
   - 最新 3-5 条摘要
   - 高风险信号（辱骂、钓鱼、诱导外链、明显违规）
5. 等待用户确认是否回复

## 2. 通知页回复 SOP（优先）

1. 在目标通知行点击「回复」入口（不要点搜索框或其他区域）
2. 校验输入框 placeholder 或上下文包含目标用户名（唯一对位凭证）
3. 输入文案（默认使用 `openclaw browser act ref=<ref_id> kind=type text="回复内容"` 逐字输入）
   - 先 `openclaw browser snapshot` 获取输入框 ref，再 `act kind=type` 输入
   - 不使用旧版 `fill` 命令：OpenClaw 统一使用 `act kind=type` 语法
4. 发送前再次确认回复对象未漂移
5. 点击「发送」按钮：`openclaw browser act ref=<send_btn_ref> kind=click`（不使用 Enter）
6. 发送后确认输入框消失/清空

## 3. 视频内回复 SOP（降级）

适用：通知页无法回复时。

1. 打开视频详情页，展开评论区
2. 锁定目标评论（用户名 + 评论关键片段）
3. 点击该条评论下的「回复」
4. 校验出现回复目标用户名
5. 输入并发送
6. 校验已发成功，再处理下一条

## 4. 风控与节奏

- 默认 one-send-per-turn：每轮只发送 1 条
- 连续回复间隔使用随机延迟（10-25 秒），不再使用固定间隔。用户明确加速时可缩短至 8-15 秒，但不可低于 8 秒。详见 `references/dy-anti-ban-rules.md` §2。
- 回复结构必须遵循 `persona.md` 中的随机化策略（A-E 变体轮换），不可每条都用同一结构。
- 命中以下提示立即停止并汇报（停止后等待 30 分钟以上再恢复）：
  - 评论过于频繁
  - 操作过快/操作频繁
  - 请稍后再试
  - 发送失败/网络异常

## 5. 长度与内容约束

- 回复建议 <= 200 字（抖音评论显示有折叠机制）
- 超长先缩写，再考虑拆分多条
- 禁止虚构个人经历
- 禁止隐性承诺（如"我后续一定整理教程"）
- 仅在用户明确要求时做额外交付承诺
- 抖音评论区氛围比小红书更直接，回复可以更简短有力

## 6. 常见故障

- 误点搜索框：点击空白处收起，重新定位通知行
- 回复对象漂移：用户名不匹配时立刻取消重来
- 连续两次发送失败：停止自动化，转人工确认
- 输入时报 `Error: fields are required`：优先判定为旧版 `fill` 命令参数不匹配（非网关崩溃），切换为 `openclaw browser act ref=<ref_id> kind=type text="..."` 后重试
- 抖音评论区加载慢：先滚动加载，确认评论列表完整后再定位
